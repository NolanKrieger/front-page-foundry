## Save completeness (the brief's main ask)
`AuditSaveTests.EverythingSavesAndGoesOnIdenticallyForThreeThousandTicks` builds one company holding every item on the brief's list and asserts it does before saving: machines mid-run on all four sources (firebox, waterwheel shaft, steam, electricity from a station **and** a dam), a mine on a worked seam (30,000 ore taken from the starter patch), a logging camp, a pump jack, two docks with orders, a sorting and a plain splitter with goods on their lanes, a trestle, stalled belts, two trucks, two trains on a signalled line, a barge, plans plus a stamped and turned blueprint, a market event and a drought, the tutorial through its first open telegram, an open commission, a grown town, cleared forest and a flooded valley (141 buildings, tick 22,021). Then: save → load → **the re-saved body is byte-identical**; the two worlds tick 3,000 times with equal hashes at every tick; cash, every vehicle's head/state/deliveries, the town's tiles and the plan list match; both take the same commands (pencil down, build, undo) and stay equal for 600 more ticks. `ACompanyOnCreditSavesThroughItsWeeklyInterestAndItsFold` saves a Hard Times company deep in debt 400 ticks before its first weekly payment: both worlds fold on the same tick, and a folded company loads folded (no ticks, commands refused). Each hidden-state bug above (HS-04/05/06/08, the train holds of HS-02) has its own failing-then-passing test.

Other hidden state checked and found saved or derived: splitter turns (`nextOut`, `laneToggle`), vehicle `dwell`/`retry`/`pathVersion`, market pending counts, glut/buy, trend and both RNGs, paper/town RNGs, `Machine.Source` (last tick's source feeds this tick's waterwheel demand: saved), `TransportLine.lastTick`, logging-camp `Trees`, power networks (rebuilt: `dirty`), rail blocks (recut), MapGen caches (pure), `TransportLine.Passed` (display only).

## Save compatibility
- Format stays **FPF1 version 1**. New state goes in an **extension block appended after the fleet** (marker `0x31585846`, then a revision number; revision 1 = plan cursor + each mine's and jack's cached yield by building id). Why not a version bump: the rc1 reader refuses any version above 1 as damage, and its store then silently falls back to `save.bak1` and rotates the good file out within two autosaves. With the block, rc1 simply stops reading before it.
- **Proven both ways against the real rc1 code** (baseline commit's `src/Sim` built in scratch): the rc1 build opened a save written by this patch and ran it on 600 ticks; this patch opened an rc1 save and ran it on (`tick 4200, 39 buildings, 1 truck, 2 plans` both ways, identical afterwards). In-suite: `AnRc1SaveWithoutTheExtensionBlockStillLoads` strips the block and loads.
- rc1 saves load deterministic but not rc1-identical in the future for the fixed items: town tiles were written sorted (HS-06) and yields/cursor were not written at all (they fall back to rc1's refresh-on-load).
- Content tables are saved by index/enum value (`Recipes.All` index for a machine's current run, `MarketEvent.All` index, `Item`/`BuildingType` bytes): tables must stay append-only or rc1 saves load wrong. `Machine.Read` now skips a saved firebox a machine no longer has instead of misreading the rest of the file.

## Proposals (not changed)
- **Home-made Motor Trucks scrap for $2,700 flat** (`Haulage.Enlist` + `World.ExecuteScrap`, 75% of the catalogue $3,600): enlisting is free, so a truck works that scraps its output earns $2,700 a truck at any volume, while selling the good crashes (K = 30: one a minute ≈ $2,735, one every 10 s ≈ $1,720). Proposal: an enlisted truck scraps for what the good would sell for now (`Market.Sell(Item.MotorTruck)`), or remembers what it cost (0) and refunds 75% of that. Balance call for the lead.
- **Plan queue order** (`World.BuildPlans`): while a plan short of money holds the queue, older plans that were passed over (flooded by a dam, lost their wood) are not looked at again until it is built, even if they became buildable and are cheap. Rare (terrain changes only); a fix would re-scan from the start after layout changes.
- **Newer save files** (`SaveStore.Load`): a file from a newer build is treated as damaged and the store falls back to an older backup, which the next autosave then rotates the newer file out behind. Proposal for the next real version bump: refuse to open (and never save over) a folder whose latest file is newer, and have the game say so.

## Reported for other owners

- **economy**: HS-07 (Paper `made` order); `Paper.Hash` uses `string.GetHashCode`, randomised per process, so `StateHash` differs between runs (fine within one process, useless for stored golden hashes); `Town.Grow` depends on HashSet order + an unstable sort (HS-06 root cause); `Town.Hash` does not cover the tiles.
- **Power (production/logistics), code reading only, not proven**: `PowerGrid.Evaluate` counts a machine's waterwheel demand from `Source` as stamped last tick, after first stamping `Electric` on members of any grid with a station/dam even when that grid delivers nothing: a machine running on the shaft is then left out of its wheel's demand.
